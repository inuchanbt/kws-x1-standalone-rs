# Selective logger hardware capture — 2026-11-17

One KWS-X1, firmware source `dfbaf84d9aa9da69734fbfeab354c02899b04922`.
[Hardware report](../../../docs/LOGGER-HARDWARE-VALIDATION-20261117.md).
KWS was OFF/PASS; ASD-PD31 was the external active Sink. The operator confirmed
the same previously used source/EPR cable/CY4500 topology; exact source/cable
model identities and calibration traceability were not recorded for publication.

## Included evidence

- `VI000101.CSV` / `VI000201.CSV`: original earlier quiet sessions, three/one
  readings; still identical in the final export.
- `VI000301.CSV` / `PD000301.CSV`: original selective AVS session 3 exports.
  Thirteen VI readings and 40 PD fragments reconstruct 24 complete packets.
- `STATUS.TXT`: original final sector/session report. No clear/reclaim was used.
- `CY4500.csv`, `CY4500.diagnostics.json`: original same-run analyzer exports.
- `CY4500.records.jsonl`: analyzer records with host timestamps removed and
  `raw_hex` clipped to the 20-byte metadata/header region plus declared data
  objects. Header bytes 16–17 and objects starting at byte 20 are retained for
  exact comparison. Unused record tails and full USB transfers are excluded.
  PD CRC/EOP/IDLE validity is analyzer metadata, not independently recomputed
  wire CRC verification by the comparison script.
- `ASD.csv`: all original measurement rows, selected columns only. Commands,
  local paths, module MACs and unrelated metadata removed. It includes setup,
  `operator-start-gate`, nine `avs-sequence` targets and `operator-stop-gate`.
  ASD ripple columns are intentionally excluded: this is not a ripple study.
- `pd-comparison.json`: digital same-run comparison, reproducible below.
- `results.json`: recorded hardware/storage summary, not all regenerated by
  the PD comparison command.
- `storage-validation.json`: recorded local CRC/CSV/preservation verification
  and original raw-dump hashes. Uninterpreted protected-sector words removed.
  The raw dumps contain pre-existing device data and **are not public**; these
  raw checks cannot be independently rerun from the public fixtures alone.
- `installation.json`: stage acceptance, operator observations and local
  before/after raw-store hash comparison, without private paths or backups.
- `quiet/`: local quiet-test results and stopped-log re-export hash comparison.
- `provenance.json`, `SHA256SUMS`: transformations, original analyzer-input
  hashes, tool identity, and public fixture checksums.
- `pc-review-checks.json`: PC negative controls and unrelated-file protection
  checks recorded before publication; distinct from hardware observations.

The raw native format is XSL1/XSP1, distinct from the PC XSC1 prototype.
These CSVs/JSONs are analysis inputs, not firmware or flashable images.

## Reproduce without device access

From the repository root (Python standard library only):

```powershell
python tools/logger_selective_compare.py tests/data/logger-selective-hardware-20261117 --session 3
python -m unittest discover -s tools -p "test_logger*.py" -q
```

The comparison reads original KWS CSVs directly, reconstructs packets, checks
CY decoded fields against its retained raw header, and matches SOP + complete
raw header + every data object + order. The tool deliberately expects the
eight-transition route. It is not a general validator for arbitrary sessions.
`--out new-result.json` writes only to a new file and refuses overwrite.

All eight KWS Request signatures uniquely match one consecutive eight-Request
subsequence of the CY recording. These Requests establish a linear clock fit;
all retained packets must then match in increasing CY order within 10 ms.
After excluding **only exact known SOP routine patterns**, every remaining CY
packet between the first matched Request and final PS_RDY must be present.
Event-ID gaps from suppression are expected.

Expected: 24/24 retained PD packets, eight complete sequences, 411 CY SOP
packets in the comparison window, 387 routine omissions, no unexplained
important omissions, max residual 3.7089061511 ms. The clock scale is
0.997157808197 and offset −36268.827590 ms. This is alignment, not calibration.

For private original raw files, the read-only verifier is available separately:

```powershell
python tools/logger_native_verify.py --export-dir PRIVATE_EXPORT --baseline PRIVATE_PRIOR_STORAGE.BIN --out new-raw-report.json
```

It checks six-sector layout, native header/record CRCs, erased tails, CSV
correspondence and unchanged prior committed/protected bytes. This strict
normal-stop audit is not a power-cut recovery algorithm or durable stop proof.

## Timing, storage and limits

ASD targets: 20,22,24,26,28,26,24,22,20 V at 0.5 A. Five programmed seconds per
step became about 59.19 seconds including serial/setup transactions. KWS
recording also included operator waiting periods. First/last retained VI were
74/149050 ms; these do not define exact session duration without an end marker.

Storage increased by 880 B: 224 B appended to the existing VI journal (session
marker + 13 readings), and 656 B for the new PD journal (header + 40 fragments).
One new 8 KiB sector was allocated; total selective allocation is 16 KiB,
including the pre-existing VI sector. All three sessions use 976 committed
native bytes. Two original protected sectors remain occupied, and two are free.

ASD setting snapshots briefly showed 0 A on return to 26 V and 0.115 A on return
to 22 V; following sequence samples recovered to approximately 0.5 A. KWS
retained 0/176 mA readings in those return regions. These are unsynchronized
observations, not matched transient timing or instrument accuracy evidence.

Only one short artificial passive sweep is covered. No general loss-free
reception, real charging duration/capacity, KWS active-Sink logging, simultaneous
screenshots, background ripple or interrupted-write recovery follows. Native
journals have no durable end marker; operator stop observations are separate.
