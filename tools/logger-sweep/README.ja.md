# KWS logger比較用AVS掃引

[English（正本）](README.md) · [日本語](README.ja.md)

既存のASD CLIを読み込む専用ランチャーです。元のASDプロジェクトは変更しません。
確認済みのv5.8.20向けで、CLIが更新された場合は接続前に止まり、再確認を求めます。

## 操作

1. `SRC → cable → CY4500-EPR → KWS-X1 → ASD-PD31` の接続にします。
   ASDのCOMポートとCY4500を使う他のアプリは閉じます。
2. **先にASDでタッチパネルのOBJ9のEPR AVSを20 V・0.5 A、LOAD ONに設定します。**
   KWSの起動とPD SNIFFの受信を確認します。loggerはまだ開始しません。
3. いつものPythonで実行します。

   ```powershell
   python D:\kws_x1_standalone_rs\tools\logger-sweep\kws_avs_sweep.py --port COM3
   ```

4. `[READY]` が出たらKWSのloggerを開始し、PCでEnterを押します。
5. `20→22→24→26→28→26→24→22→20 V` を各段最低3秒、負荷0.5 Aで測定します。
6. `[DONE]` では20 V・0.5 Aを維持して待ちます。
   **KWSを停止して`LOGGER STOPPED`を確認した後にPCでEnter**を押します。
   ここで初めて通常終了のLOAD OFFとCY4500の停止・保存を行います。

保存先は毎回自動作成する `CY4500_logs\kws_avs_*` フォルダーです。
`ASD.csv`、`CY4500.csv`、関連診断ファイルが入ります。取り出したKWSのCSVも同じ
フォルダーへコピーしてください。`$stamp`の更新や既存ファイルの削除は不要です。
接続がCC2なら`--cable-set cc2`を追加します。`--plan`は機器を動かさず手順だけ表示します。

開始前の5 V切り替え・LOAD OFF・プロトコル再初期化はありません。
既存AVSの確立はランチャーの前に行う必要があります。電圧・電流の読み取りだけでは
契約中PDOを証明できないので、タッチパネルのOBJ9のAVS設定を確認してください。
CY4500の通信証拠確認は最初の電圧変更22 Vから行い、以降も維持します。

Enter待ちでも測定とCY4500の動作確認を続けます。ただし、動作を引き継いだ後の
**異常やCtrl+Cでは即座にLOAD OFF**します。保存完了まで無条件に給電し続ける機能では
ありません。開始条件が合わない場合は、出力を変更せず終了します。

模擬機器を使う7件のテストを用意しました。実機を動かすテストではなく、今回の
給電維持とCY4500/KWSの同時記録は実機での確認が必要です。

## タッチパネル番号

`--panel-object 9`（既定値）は空のPDOを除いた9番目を選択します。
今回の電源ではパネルOBJ9＝取得データのObject 11です。開始時に対応と内部Gearを表示し、EPR AVSの範囲を検査します。
CSVには取得データ側の番号を残します。内部Gearは従来と同じ`0x12`です。
9件の模擬テストは成功、実機は未検証です。入力待ちの更新は下記を参照してください。

## Enter不要の自動開始

`--start-delay 10`を付けると事前確認後に10秒カウントダウンし、Enterなしで掃引を開始します。
カウントダウン終了までにKWSの記録を開始してください。通信処理で待ち時間が延びる場合があります。
終了後は20 V・0.5 Aを維持します。KWSを停止してLOGGER STOPPEDを確認してからEnterを押します。
Enterは標準入力で受け取り、受信メッセージを表示します。入力終了はエラー扱いで停止処理を行います。
通信の生データ表示は既定で抑制します。必要なら`--verbose`を指定してください。
模擬テスト12件成功、実機は未検証です。前回開始待ちから進まなかった入力側の原因は未確定です。
