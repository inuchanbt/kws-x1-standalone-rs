# 充電logger v0.3（試作版）

[English（正本）](CHARGING-LOGGER.md) · [日本語](CHARGING-LOGGER.ja.md)

キャプチャと排他のビルドです。`--features charging-logger` を指定すると、
画像保存／BMP出力を電圧・電流の記録／CSV出力に置き換えます。
通常ビルドは従来のキャプチャ版です。logger版のRelease配布ファイルは未公開です。

## 操作

1. 通常起動後、左右を約0.5秒同時押しして記録を開始します。
   `LOGGER REC 1s - L+R STOP` が記録中の表示です。同じ操作で停止します。
2. 校正済み電圧（mV）、符号付き電流（mA）、セッション番号、開始からの経過時間（ms）を
   約1秒間隔で保存します。区間平均ではなく、その時点の測定値です。
   読み取り失敗時は保存を飛ばすため、時刻の間隔が広がります。
   開始時刻に基づく締切で周期を進め、遅れの累積や取り戻すための連続保存を避けます。
   停止時は未保存のPDキューを処理するため、`LOGGER STOPPED` を待って抜いてください。
3. 測定を終えて接続機器を外し、左右を押しながらPCの5 V USBに接続します。
   読み取り専用の `KWS LOGGER` ドライブから `LOG00001.CSV`～`LOG00006.CSV` をコピーします。
4. 消去する場合は、左右＋Backを押しながら5 Vで起動し、
   `ERASE LOGS+CAPTURES?` で全ボタンを離してからOKを2秒長押しします。
   Backでキャンセルできます。完了後は抜き差しして再起動してください。

**v0.2の消去は、保存用6区画内の既知のキャプチャも対象です。**
必要な画像は、先にキャプチャ版で取り出してください。logger版ではBMPを出力しません。
未知のデータは消しません。空きができなかった場合は `NO SPACE - UNKNOWN DATA` と表示します。

## 保存容量とCSV

- 保存先は `0x62000–0x6DFFF` の8 KiB×6区画だけです。
  工場データ・設定・ENERGY MEMORY（`0x78000`／`0x7A000`）はloggerの割り当て・消去対象外です。
- 各区画は16バイトのヘッダーと511サンプルを格納します。
  48 KiBすべて空きなら3,066サンプル、PD記録がなければ1秒間隔で約51分です。
- 記録を開始するたびに新しいセッションと空き区画を使用します。
  停止したセッションの未使用部分は再利用しません。短い記録を繰り返すと早く満杯になります。
- 満杯や書き込み失敗で記録を停止します。記録中の自動消去・上書きはありません。
  再起動後は停止状態です。
- 1ファイルは1物理区画です。長いセッションは複数ファイルに分かれます。
  測定値とPDではCSVの列が異なるため、下記の復元ツールで結合します。
  ファイル番号はセッション番号ではありません。

CSVはUSB読み出し時に生成します。本体には16バイトのコンパクトな記録を保存し、
チェックサムを最後に書き込みます。未完了・破損レコードは出力しません。
ヘッダー書き込みや消去の途中で電源が切れると、未知の区画として保持され、
通常の消去では回復できない場合があります。

## v0.3：PD記録とAVS掃引

外部のAVSトリガー／シンクで掃引し、KWS-X1はパススルーで観測します。
開始前にPD SNIFFが受信できていることを確認してください。logger開始でスニファーを
起動・復旧する機能はありません。シンク動作中のRX/TX、CHARGER/CABLE照会は対象外です。

- 生ヘッダー、MessageID、SOP種別、最大7個の生データオブジェクトを保存します。
  時刻は測定値と同じ開始基準のms単位ですが、ソフトウェアが受信した時刻です。
  CY4500とは別時計なので、同じREQUESTとペイロードを複数箇所で照合してください。
- 受信側は32件のRAMキューへ渡すだけです。測定側で1回につき最大4件を処理し、
  パケット間でI2Cを解放して1 ms待ちます。CRCは受信時に検証済みですが保存しません。
  Extendedのチャンク再構成や、受信できる種類の拡張は行っていません。
- キューあふれは `QUEUE_DROPPED`、記録中のスニファー終了は `SNIFFER_STOPPED` です。
  終了理由はPD SNIFFで確認します。これらも保存容量が必要で、欠落ゼロの保証ではありません。
- PDと測定値は別区画を同じ6区画の中から確保します。PDは1パケットにつき
  「1＋データオブジェクト数」レコードを消費するため、通信量で記録時間が短くなります。
  片方に余りがあっても、もう片方が新しい区画を確保できないとFULLになります。
- 電源断やFULLで途中になったパケットは復元時に `INCOMPLETE` と表示します。
  v0.2の測定CSVは引き続き読み出せます。保存領域と消去対象は変えていません。

同じ取り出し操作で得たCSVをすべて `logs` にコピーして実行します。

```powershell
python tools/logger_decode.py "logs/LOG*.CSV" --out logs/decoded.csv
```

測定値、PDヘッダー／データの16進表記、MessageID、数値のメッセージ種別、
欠落通知を同じ時系列へまとめます。消去後にセッション番号が再使用されるため、
異なる取り出し回のファイルを混ぜないでください。

最初の比較は、対応するAVS範囲で負荷を一定にし、1段約3秒、短い範囲を1往復する想定です。
CY4500とloggerを先に開始し、掃引後に停止します。REQUEST／ACCEPT／PS_RDYと
ペイロードを照合し、まず欠落通知と不完全パケットの有無を確認します。
1秒測定は安定後の電圧確認向けで、過渡波形の測定には向きません。
保存形式の詳細は[英語正本](CHARGING-LOGGER.md#event-storage-format)を参照してください。

## ビルド・書き込み・検証状況

```powershell
cargo test -p firmware-core --lib --locked --offline
cargo build -p firmware --release --target thumbv7em-none-eabihf --features charging-logger --locked --offline
```

依存関係を取得済みの環境向けのコマンドです。ビルドだけでは機器に書き込みません。
ローカル試作ファイルは `build/charging-logger-v0.3` にあります。
同じビルドのupper／mainとSHA256SUMSを使い、[書き込み手順](FLASHING.md)に従ってください。

v0.2では38件のホストテスト、ARMビルド、X1C構造検査を通過しています。
KWS-X1 1台で書き込み、消去、約50秒の記録と電源を抜いた後のCSV取り出しを確認しました。
CY4500-EPRの記録には2回のREQUEST→ACCEPT→PS_RDYとそれぞれのGoodCRCがあり、
CSVの電圧変化と整合しています。両ログの時刻は同期していません。

v0.3はパッシブ受信したPDメッセージも保存します。実機での確認はこれからです。 フラッシュ書き込みは短時間割り込みを止めます。
今回の通信が書き込みの瞬間と重なった保証はなく、PDへの無影響を保証するものではありません。
長時間記録、書き込み／消去中の電源断、PD同時動作の厳密な検証は未完了です。
詳細は[検証記録（英語正本・日本語要約）](LOGGER-VALIDATION.md)を参照してください。


## v0.4 保存領域の回復

従来の消去は元ファーム由来の未認識データを残し、空きが1区画だけでも成功と表示していました。
今回の05・06だけ使う状態、約40秒でPD区画が満杯になる状態と整合します。
ただし現在の全区画の内容はCSVだけでは確定できません。

この実機向けビルドは保存済みCAPFLASH-original.BINの区画ごとのSHA-256を組み込み、
認識済みログ・キャプチャに加え、バックアップと完全一致する旧データだけを消去します。
一致しないデータは残します。HASHの自己検査失敗時は消去しません。
記録中の消去は行わず、設定・工場データは対象外です。

必要なデータを保存してから、左右＋Backで接続し、CLEAR LOG+BACKED DATA?で離してOKを2秒押します。
CLEARED - 6/6 FREEを確認してください。PARTIAL - N/6 FREEは未解放区画が残っています。
このビルドは保存済みバックアップに対応した実機専用です。

GoodCRC・EPR KeepAliveも生データとして保存するため、今回の通信量では全6区画でも約3分が目安です。
51分は測定値だけの場合の上限です。区画をまたぐPDの続きも含め、LOG*.CSVをすべて取り出してください。
満杯時にパケットの途中だけ書く処理も修正しました。実機での6/6空きと掃引完走は未確認です。


Latest v0.4 hardware result / 最新の実機結果: [64-second AVS capture and reproducible comparison](../tests/data/logger-avs-20261113/README.md). Event-sector rollover and all eight voltage-change sequences were verified on one device.
