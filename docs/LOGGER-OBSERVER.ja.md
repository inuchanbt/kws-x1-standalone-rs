# 受信専用ロガー v0.7候補版

[英語の正本](LOGGER-OBSERVER.md)。`--features logger-observer`でビルドします。
v0.5の単一ファイル書き込みとAVS観測は実機で確認済みです。
v0.7の追記保存・USB書き出しは実機で10記録のCSV・生データ一致まで確認済みです。
区画跨ぎ・同時計測の参照機との照合は次の試験です。

## FULLの原因と修正

届いたSTATUS.TXTでは6区画すべてが正常なログ領域でした。
記録1は測定53行・PD511+165行の3区画、記録2/3/4は測定7/3/2行で各1区画。
ヘッダー込みの使用量は11,952 / 49,152バイトで、停止済み記録の残りが使えないため
区画だけが埋まっていました。記録2〜4にPDがない理由までは、この情報では断定しません。

v0.7では新しいXLG2/XLE2形式を使い、停止・再開や電源の入れ直し後も区画の残りへ
追記します。記録番号の境界にはチェックサムを最後に書く16バイトのマーカーを入れ、
既存行を上書きしません。書き込みが中断した場所は再利用せず、前の正常な行を残します。
PDパケットはマーカーも含めて収容可能か確認してから保存します。
記録中の消去、自動消去はしません。

旧XLG1/XLE1ログも読めますが、旧形式の余白には追記しません。
**今回の旧形式で満杯の状態は、CSVとSTORAGE.BINを退避してから、一度だけ確認付き消去が必要です。**
更新の書き込みだけではログ領域は消えません。

32記録を上限とし、到達時は`LOGGER SESSION LIMIT`と表示します。
実容量が先に尽きた場合は`LOGGER FULL - COPY/CLEAR`です。
空き区画0でも新形式の余白があれば開始できます。
物理容量48 KiB自体やGoodCRCなどの記録量は変わりません。

## ファイル名

| ファイル | 内容 |
| --- | --- |
| VI000101.CSV | 記録0001の電圧・電流 |
| PD000101.CSV | 記録0001のPD受信 |
| VI000201.CSV / PD000201.CSV | 次の記録0002の組 |
| STATUS.TXT | 各区画の種類・最初の記録番号・使用スロット数 |
| STORAGE.BIN | 専用6区画の読み取り専用バックアップ |

末尾01は名称の互換性のため残しています。同一記録のPDが複数区画にまたがっても
1本のPDファイルにまとめるため、これまでの3本はVIとPDの2本になります。
PDデータがない記録にはVIだけができます。CSVの列は変えません。
STATUSのSLOTSは記録境界マーカーも含み、FIRST IDは区画の先頭の記録番号です。
LATEST SESSIONが最後の記録番号を示します。

## 実機での確認

スイッチは**OFF（パススルー）**です。ON起動で受信しないこと、受信中のON切替で
停止することはユーザー確認済みです。再開にはOFFに戻して接続し直します。
左右同時長押しで記録開始・停止、`LOGGER STOPPED`を待って切断します。
PCの5 Vで左右を押しながら接続するとUSB書き出しです。
消去はPCの5 Vで左右＋戻るを押して接続し、離してから確認画面でOKを2秒。
退避済みの必要なログを消してよい場合だけ実行し、終了後は再起動します。

`build/logger-observer-v0.7/FLASH.md`の手順とハッシュでfirmware.X1Cを一度書き込みます。
旧ログを退避・確認付き消去したら、消さずに6回の短い開始・停止を試してください。
途中で一度電源を入れ直し、過去の行が保たれることとVI/PDの番号の対応を確認します。
静かなPCの5 VではVIだけでも正常です。PDは外部ASDによるAVS試験で確認します。
その後、従来どおり9点掃引し、KWS・ASD・CY4500を照合します。

ホストでは32回の短時間記録を2区画へ追記、電源再投入、空き区画ゼロでの再開、
中断書き込み、パケット跨ぎ、64ファイルのFAT・CSV・バックアップを検証しています。
実機の書き込みやUSBの時間特性、長時間記録などの確認はまだ必要です。

## v0.7の10回連続記録を実機確認（2026-11-13）

退避された10記録・16 CSVをSTORAGE.BINと照合し、全行一致とCRC正常を確認しました。
測定41行、PD断片276行から完全なPD184パケットを再構成でき、不完全な組・
キュー落ち通知・受信停止通知はいずれも0でした。PD記録IDも各記録内で連続しています。
VIは1区画で記録1〜10、PDは1区画で記録5〜10を保持し、4/6区画が完全に空いています。
ヘッダー・境界マーカー込みの使用量は5,328 / 49,152バイト（10.84%）。
再利用できる余白を含めて43,824バイトが空白です。

記録1〜4にPDがないことは生データと一致しますが、当時の通信・受信状態までは
このデータだけでは断定しません。電源再投入の手順もデータには残りません。
今回は同時計測の参照ログがないため、バス上の受信漏れゼロという判定はしていません。

次は消さずに記録11で従来の20→28→20 V掃引を行い、VI001101.CSV / PD001101.CSVを
ASD・CY4500と照合します。現在のPD余白は230スロットで、長めの掃引なら区画跨ぎと
1本のPD CSVへの統合も確認できます。

## v0.7 AVS掃引の三者照合（2026-11-13）

kws_avs_qpv94iemの試験前には消去したとユーザー確認済みなので、今回は記録1です。
前の10記録を残した記録11への追記試験ではありません。
添付されたVI000101.CSVは56行、PD000101.CSVは706断片で、完全なPD476パケットを
再構成できました。全476件がCY4500の連続区間（0起点16〜491）と一致し、
共通区間の不一致・不完全パケット・キュー落ち通知・受信停止通知はいずれも0。
8回の要求→Accept→PS_RDYとペイロードも一致しています。CYのCRC/EOP/IDLE異常も0です。

STATUSはPDを511＋195スロットの2区画として報告し、1本のPD CSVに統合されています。
この境界は40.545秒のイベント345のヘッダーとペイロードの間に当たり、同イベントも
正常に再構成してCYと一致しました。3/6区画は空きです。
STORAGE.BINを機器からローカルへ退避後、3ヘッダー・762記録のCRCを独立検証し、
CSV全行との一致と物理配置も確認しました。未使用部分はすべて消去状態です。
使用量は12,240 / 49,152バイト、空白は36,912バイトです。

ASDとの9点の中央値差はKWS−ASDで電圧+13.5〜+15 mV、電流+2 mAです。
測定位置・配線・計器のずれ・時間差を分離していないので精度や校正値とは判定しません。
KWSは戻りの26/24 Vで30.020/36.024秒に0 mAを記録し、次の標本で約0.502 Aへ戻っています。
ASDの過渡時の低電流警告とも整合しますが、同時刻の過渡応答比較ではありません。
